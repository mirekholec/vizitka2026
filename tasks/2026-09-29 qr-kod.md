# Plan: Hidden QR tab for the contact card

## Problem and approach

Add a private, unobtrusive way to show a QR code on the existing static contact-card page. The normal first visit remains the current contact card with no visible tabs. Tapping the hidden area at the bottom reveals the tabs and selects QR. The QR payload is exactly `https://holec.ai/me`.

Keep the implementation static and self-contained in the existing page: no framework, backend, QR service, or external runtime dependency. Render the QR from an embedded static SVG and preserve the current visual design, links, vCard download, and ADNP section.

## Notes and decisions

- The selected tab is stored locally per browser/device. A first visit defaults to Vizitka; on return the last selected tab is restored while the tab bar remains hidden. Tapping the bottom area toggles the tab bar; its first activation selects QR.
- Use a transparent, keyboard-accessible hit target at the bottom edge, respecting mobile safe areas. Keep it visually absent during normal use.
- Embed the QR code locally so it contains only the HTTPS URL and continues to work without a third-party QR service.
- The existing source is a single static HTML file with inline styles. No `DECISIONS.md` exists, and this feature does not introduce a framework, backend, or other architectural change.
